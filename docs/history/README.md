# Implementation reports and release notes

Per-release records of what was built, what was rejected and what evidence was produced. They
are kept because a decision is only auditable if the reasoning that produced it survives, and
they are here rather than in `docs/` because they are a record of the past rather than a
description of the present.

Nothing here is the current state of the tool. For that, read:

- [README](../../README.md) for what the tool does and how to run it;
- [METHODOLOGY](../../METHODOLOGY.md) for how each number is computed;
- [LIMITATIONS](../../LIMITATIONS.md) for what the results cannot tell you;
- [DECISIONS](../../DECISIONS.md) for the standing decisions these reports implement;
- [STATUS](../../STATUS.md) for where the work currently stands.

Reports are named `implementation_report_v<version>.md` and release notes
`release_notes_v<version>.md`. A `_review` suffix marks a report reviewing a completed version
rather than implementing one.
