# Custody records for accepted official artifacts

This directory holds one JSON custody record per accepted official artifact. A record is a
fingerprint, not data: per-file digests plus content-level invariants of the normalized price
series. **No official price is ever recorded here**, which is what makes these files safe to
commit while the artifacts themselves stay outside Git.

Counts under `interval_counts_by_delivery_year` use the CET/CEST market clock, not UTC, so a
market day belongs entirely to one delivery year. This differs by one interval at a year
boundary from a UTC-grouped count; see the procedure document for the worked 2020 case.

`accepted-fundamentals-feature-table.json` fingerprints the combined point-in-time feature table.
Its `content` section is empty by construction: no file in that artifact is a canonical price
history, so the record holds per-file byte digests only, and a feature value can no more be
recovered from it than a price can from the others.

This directory covers **retrieved official artifacts only**. Derived evidence produced by this
project from an already-custodied history — the `annual-replay-decomposition` artifact, for
instance — gets no record here: it has no provider that could revise it, and its inputs are
already fingerprinted, so it is guaranteed by reproduction rather than by custody (decision
entry 2026-08-28).

A record is generated by the `Record official artifact custody` workflow, reviewed, and then
committed here. Once a record is committed, that workflow verifies against it instead of
regenerating it, and fails on any difference. To regenerate one deliberately — for a re-record
against a replacement artifact — dispatch that workflow with `record_mode: record`. It writes the
new record to the run's artifact for review and never to this directory, so replacing a record
stays a reviewed commit plus a decision entry. Never delete a record to make the workflow
regenerate it: that is indistinguishable from tampering with the evidence.

Do not edit a record by hand, and do not overwrite one to make a verification pass. A
difference means either the stored copy is corrupted, the official publication was revised, or
this project's own normalization changed — three different findings with three different
responses, set out in
[`../official_artifact_custody.md`](../official_artifact_custody.md). Replacing a record is a
decision that belongs in `DECISIONS.md`.
